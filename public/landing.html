How it works

Three loops, from one ticket to a whole season.

  1. 01

    Every ticket: a start time per dish

    The steak goes on before the fries so both leave the pass together. Each fire time weighs food sitting against a courier or guest waiting, and shows its arithmetic.

  2. 02

    Every finished dish: one training step

    The kitchen's own timestamps label the data: done minus start, in seconds. No manual tagging. The network predicts each dish before it learns from it, so its error is honest.

  3. 03

    Every three weeks: a model release

    The retrained network replaces the one in production only if it was more accurate on the last three days. If not, production stays as it is.

A real network, small on purpose

PrepNet learns how long each dish really takes in your kitchen, as a correction on top of the menu's estimate. With no data it predicts the menu exactly; every finished plate moves it toward the truth.

  • Architectureitem and station embeddings → 16 → 8 → 1, SiLU, per-dish residual bias
  • TrainingAdamW on replayed mini-batches, Huber loss, gradient clipping at 1.0
  • Labelsself-labelled from the kitchen's own timestamps; no manual tagging
  • Releaseschampion vs challenger every 21 days, promoted only when better
  • Verifiedbackpropagation checked against finite differences on every parameter

What it doesn't do (yet)

  • The results above come from a seeded simulation of one kitchen, not a production POS.
  • On a single cold shift the network matches the menu's estimates; the gains come over weeks of service.
  • No language model is in the firing decision. The AI agent only adjusts training, and only when a held-out check says it helps.
  • It doesn't model staff breaks, station changeovers or a dropped plate.
